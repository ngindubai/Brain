## Story 1: AI Mode conversations are leaking into your ordinary Search Console reports

**Source:** Search Engine Journal | https://www.searchenginejournal.com/the-ai-conversations-leaking-into-your-search-console/585663/
**Related vault notes:** [[SEO Portfolio]], [[Comparison Network]]

Google's AI Mode treats every message in a conversation as a fresh search query, including follow-ups like "yes," "what about Claude?" or "is it free?". Those fragments don't stay siloed in the new Generative AI report — they show up mixed into the ordinary Performance report, the one everyone already checks, because Google's two reporting systems have different retention rules and only one of them (the older one) captures everything indiscriminately.

John Mueller confirmed the mechanic directly: "A follow-up question inside AI Mode counts as a brand new query." Whatever content the AI Mode response drew from gets attributed back to that conversational fragment in Search Console, sitting next to legitimate keyword searches with no visual distinction.

The piece cites a 16-month sample where one property picked up 1,127 AI-related queries generating 20,300 impressions — small next to total traffic but real session data, not noise. The fragments split into useful buckets: reply artifacts ("yes," "sure"), pivot comparisons ("what about Resend?"), full conversational questions, synthetic probes from AI-visibility tracking tools, and occasionally entire agent system prompts logged as if they were searches. The standout pattern: impressions vastly outnumber clicks, confirming what most of us assume — people read the AI answer and never land on the page.

For the portfolio this is a genuine intelligence source, not a nuisance to filter out (well, some of it is, but not all). Pivot-comparison queries ("what about X") on pet-transport, funeral-repatriation or the comparison network sites tell you what alternatives users are weighing inside AI Mode — content gaps worth building comparison pages for. The action item isn't optimising titles for these queries, it's strengthening the passages AI Mode is actually pulling from, since that's what determines whether the portfolio gets cited in the answer at all.

**Action items:**
- Pull the Performance report query list for each portfolio and comparison-network property and eyeball it for AI-Mode-shaped fragments (short, conversational, no commercial intent phrasing).
- Cross-reference against the Generative AI report to separate AI Overview citations from AI Mode conversation fragments — they're different signals.
- Treat repeated pivot-comparison fragments as a content brief, not a query to rank for.

## Story 2: Google Ads switches on conversion-based customer list auto-classification today

**Source:** Search Engine Land / Search Engine Roundtable (via web search, primary SER article inaccessible) | https://www.seroundtable.com/google-ads-conversion-based-customer-lists-41529.html
**Related vault notes:** [[Comparison Network]], [[SEO Portfolio]]

Google confirmed data processing for conversion-based customer lists begins today, 18 August 2026, for any Google Ads account running both Enhanced Conversions and Customer Match that hasn't already turned the feature on manually. From today, Google auto-assigns a customer type to every eligible list and stops allowing eligible lists to sit unclassified. No advertiser action was required to activate it — it simply switches on unless someone opted out in account settings before today.

This is a targeting-accuracy feature, not a policy change with penalties attached, but it does change what audience segments Google is auto-building from first-party conversion data across any account using both features together. For the UAE comparison network sites, which run on lead-value optimisation and likely have Enhanced Conversions wired up for CPA bidding, this is worth a five-minute look today rather than discovering an unexpected new audience segment in three weeks.

**Action items:**
- Check each Google Ads account (comparison network especially) for Enhanced Conversions + Customer Match combination.
- If already classified deliberately, confirm the auto-assigned customer type matches; if not, decide whether to keep it on or opt out.
- No action needed on accounts that don't run both features together.

## Story 3: Google shuts off the Content API for Shopping, Merchant API takes over

**Source:** Search Engine Roundtable / multiple trade coverage (via web search) | https://www.seroundtable.com/google-merchant-api-content-api-for-shopping-39958.html
**Related vault notes:** [[Products]]

Today is the actual cutover date Google announced for retiring the Content API for Shopping. Merchant API — in beta since May 2024 — is now the sole programmatic interface for Merchant Center. Any integration still calling Content API endpoints stops working today: product feeds, Shopping campaigns and data pipelines built on the old API break, not degrade.

Manual uploads, scheduled fetches and Google Sheets feeds are unaffected — this only bites custom or third-party programmatic integrations. Shopify's own Google & YouTube channel app handles the migration automatically, but there's a known side effect flagged in recent days: reinstalling that Shopify app before today's deadline can reset product item IDs in Merchant Center, which makes Google treat existing products as brand-new listings and restarts Performance Max learning from zero. Google Ads Liaison Ginny Marvin has acknowledged the reports; no fix is out yet.

**Portfolio relevance check:** none of the five SEO portfolio sites or five comparison-network sites run Google Shopping campaigns or Merchant Center feeds, so this is a non-event for Orwell directly. Flagging only because it's a hard cutover happening today and worth ruling out explicitly rather than assuming.

## Story 4: llms.txt gets its first major revision since launch

**Source:** Search Engine Journal | https://www.searchenginejournal.com/llms-txt-v2-formal-markdown-linking-ai-agents/586119/
**Related vault notes:** [[SEO Portfolio]], [[Agent Org]]

Jeremy Howard (Answer.AI), who created the original llms.txt spec, published a V2 revision this week after two years of real-world use — the article ran today. Two changes: sites can now expose Markdown versions of pages either as `.html.md` or a straight `.md` extension, and two new HTML link relations (`rel="alternate" type="text/markdown"` and `rel="describedby"`) let agents formally discover the Markdown version and the governing llms.txt file, as HTML tags or HTTP headers.

Adoption is real — thousands of sites publish llms.txt now, Mintlify auto-generates it, and Anthropic, OpenAI and Google's Gemini team all publish their own for developer docs. But Google Search's own guidance is unambiguous: this "will neither harm nor help your site's visibility or rankings" because Search doesn't currently consume these files. The audience is coding agents and IDE tools pulling documentation, not search ranking systems.

Relevant to Orwell only as a technical-debt-adjacent watch item, not an action item today. It sits in the same "agent-readiness" bucket as the OKF and Lighthouse-for-agents work Marie Haynes has been covering through the year — worth a line in the technical SEO audit backlog, not worth doing this week.

## Story 5: Google splits visible and invisible AI watermarks in Gemini

**Source:** Search Engine Journal | https://www.searchenginejournal.com/google-lets-you-turn-off-visible-watermarks-in-gemini/586145/
**Related vault notes:** [[SEO Portfolio]]

Google added a toggle letting users turn off the visible watermark on Gemini/Flow-generated images, video and music (Nano Banana, Omni, Lyria), announced today by Google Labs VP Josh Woodward as "balancing creative control and safety." The invisible layer — SynthID plus C2PA metadata — stays embedded regardless of the toggle, and Search's "About this image" verification still works off that invisible layer, not the visible mark. The toggle won't appear in India, South Korea or Vietnam, where visible AI watermarks are a legal requirement.

Worth noting alongside yesterday's story that Google paused AI-generated images inside AI Overviews: taken together, these read as Google tightening the distinction between "how content looks to a user" and "how content is verified" rather than loosening standards. No direct action item for the portfolio, but it's the context for anyone using AI-generated imagery on portfolio sites — the visible watermark being optional doesn't change what Google can detect.
