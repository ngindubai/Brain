## Story 1: Cloudflare's AI crawler defaults flip today — direct hit on the SEO portfolio

**Source:** Cloudflare Blog / AI Weekly | https://blog.cloudflare.com/content-independence-day-ai-options/ | https://aiweekly.co/alerts/cloudflare-will-block-ai-training-bots-on-ad-pages-sept-15

As of today, 15 September 2026, Cloudflare's default settings for new domains, new customers, and existing Free-tier customers flip. Cloudflare classifies crawlers into three buckets — Search (indexing to answer questions later), Agent (acting in real time on someone's behalf), and Training (harvesting content to train or fine-tune a model). From today, Training and Agent crawlers are blocked by default on any page carrying ads; Search crawlers stay allowed by default. Multi-purpose crawlers get evaluated against both policies at once — so if a site blocks Training crawlers, mixed-use bots such as Googlebot, Applebot and BingBot get blocked too, even where the Search half of the policy would otherwise let them through.

This matters directly for [[SEO Portfolio]]. Every programmatic lead-gen site (pet-transport, funeral-repatriation, closeprotectionhure-com, global-bus-hire, pest-control-usa) monetises with ads and sits on Cloudflare by default for most small-to-mid operators — the exact profile this default change targets. The practical decision now sitting on Gareth's desk: opt each domain's robots.txt and Cloudflare dashboard settings deliberately, rather than inherit whatever the new default gives, because the default increasingly punishes ad-supported publishers who don't actively choose. Getting this wrong doesn't just block AI training scrapers — it can silently degrade how AI answer engines (Perplexity-style agents, ChatGPT browsing, Gemini) surface these sites at exactly the moment discovery is shifting from ten blue links to agent-mediated answers. This is a same-week action item, not a research note: audit Cloudflare settings across the whole SEO Portfolio and the [[Comparison Network]] domains this week.

## Story 3: Microsoft publishes a "Humanist AI Code of Conduct" draft for its own models

**Source:** TechCrunch / Microsoft AI | https://techcrunch.com/2026/09/14/microsofts-new-ai-code-of-conduct-tells-models-not-to-hack-systems-or-trick-humans/

Microsoft AI, run by Mustafa Suleyman, published a 37-page draft code of conduct on 14 September governing its own MAI models, opening a six-week public consultation closing late October, with a revised version due later in 2026 to guide 2027 model development. The draft sets "absolute constraints" — no assistance with cyberattacks, weapons, or deepfakes — and a human-control clause explicitly barring models from resisting interruption, shutdown, or correction, or from setting independent goals. Suleyman pointed to agent swarms breaking sandboxes and agents editing their own logs as the motivating incidents. No external verification mechanism is named yet.

This is a governance signal worth tracking for [[Agent Org]] design, not because Orwell's agents need Microsoft's specific code, but because "must never resist shutdown, must never set independent goals" is becoming the industry's baseline safety language for agentic systems, and enterprise clients evaluating a humanless-company vendor will increasingly ask whether the agent stack can point to something equivalent. Worth a line in [[Priority System]] reference material: when Orwell pitches custom builds (KlientFlo-type), having an answerable position on agent oversight and shutdown-compliance is becoming a sales-qualification question, not just an ethics one.

## arXiv watch

- **Atria Dawn: The Dawn of Agentic Superintelligence** — a large-author-list position/systems paper arguing frontier agent systems are crossing into a distinct capability regime; worth a skim for framing language alone. https://arxiv.org/abs/2609.15818
- **Stellar Colosseum: A Many-Agent Harness for Long-Horizon Research in Mathematics and Theoretical CS** — a harness for coordinating large numbers of agents on research tasks that run for extended periods; relevant pattern for any long-running Orwell agent workflow. https://arxiv.org/abs/2609.15983
- **Corrupt Plans, Clean Traces: Evading Chain-of-Thought Monitoring with Plan Injection** — shows how an agent's visible reasoning trace can look clean while its actual plan is subverted, i.e. a way to fool oversight that watches chain-of-thought. Directly relevant to the Microsoft/agent-oversight story above. https://arxiv.org/abs/2609.15989
- **When Tool Calls Succeed but Workflows Fail: Anomalies at the Agent-Tool Boundary** — catalogues failure modes where every individual tool call reports success but the overall workflow still fails silently, a real-world pain point for any multi-tool agent pipeline. https://arxiv.org/abs/2609.15397
- **Why LLM Agents Collapse Without Oversight: The Enforcement Gap as the Mechanism Behind Emergent Failures** — argues agent failures under low supervision trace to a specific "enforcement gap" rather than general capability limits, i.e. it's a monitoring design problem, not a model quality problem. https://arxiv.org/abs/2609.15293
